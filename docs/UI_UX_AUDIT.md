# Audit UI/UX KINO Laundry POS

## Ruang lingkup dan metode

Audit ini membaca dokumentasi arsitektur serta halaman, komponen, data, dan CSS di `src/`. Tidak ada browser preview atau screenshot yang diperiksa, sehingga ini adalah **audit berbasis kode**, bukan klaim hasil inspeksi visual saat runtime. Penilaian tablet mengacu pada breakpoint dan ukuran yang tertulis di CSS. Rekomendasi tidak menghapus kemampuan aplikasi.

Arsitektur tampilan saat ini memakai satu entry React di [`main.jsx`](../src/main.jsx) dan pemilihan halaman berdasarkan role di [`Root.jsx`](../src/app/Root.jsx), tanpa React Router. Halaman Kasir dan Owner berpindah melalui state menu; absensi karyawan serta gerbang buka shift adalah tampilan tersendiri. Styling utama dibagi ke [`style.css`](../src/style.css), [`pages.css`](../src/features/cashier/styles/pages.css), [`history.css`](../src/features/cashier/styles/history.css), [`operations.css`](../src/features/cashier/styles/operations.css), [`reports.css`](../src/features/cashier/styles/reports.css), [`owner.css`](../src/features/owner/styles/owner.css), [`owner-dashboard.css`](../src/features/owner/styles/owner-dashboard.css), [`owner-single-outlet.css`](../src/features/owner/styles/owner-single-outlet.css), [`entry.css`](../src/shared/styles/entry.css), dan [`typography.css`](../src/shared/styles/typography.css).

Severity menunjukkan dampak terhadap pekerjaan operasional: **Tinggi** menghambat transaksi atau dapat membuat pengguna salah memahami data; **Sedang** menambah beban kognitif/ketidakjelasan; **Rendah** terutama berdampak pada konsistensi atau kosmetik.

## Evaluasi tablet touchscreen

- **Lebar kerja POS:** CSS memberi sidebar 224px dan keranjang 278px pada breakpoint sampai 1250px. Pada tablet landscape 1024px, sidebar dan keranjang tetap bersamaan; ruang katalog menjadi sempit. Keranjang baru berpindah menjadi panel overlay pada `max-width:1000px`.
- **Breakpoint:** pada `max-width:1000px` sidebar 210px dan keranjang disembunyikan ke tombol keranjang mengambang; pada `max-width:760px` sidebar menjadi drawer dan navigasi bawah muncul. Perubahan pola tepat untuk ponsel, tetapi rentang tablet landscape sekitar 1001–1200px masih mempertahankan layout padat desktop.
- **Ukuran sentuh:** beberapa kontrol CSS berukuran 27–43px; tab kategori Kasir pada aturan mobile setinggi 30px; tombol navigasi Owner minimum 38px. Sebagian ikon 34px. Nilai ini berisiko sulit disentuh cepat; target utama POS sebaiknya minimum 44×44px.
- **Tabel:** Order/History/Inventory/Coins mempertahankan banyak kolom dan scroll horizontal; pada tablet sentuh ini memperlambat pemindaian dan membutuhkan gestur yang kurang terlihat.
- **Keranjang dan scroll:** total serta tombol bayar harus tetap mudah dijangkau saat katalog/daftar panjang digulir. Gunakan panel keranjang yang konsisten pada landscape, dan drawer yang mudah dibuka pada portrait.
- **Form:** ukuran input umumnya sekitar 38–43px tetapi label dan instruksi sebagian sangat kecil. Ruang input/label perlu diukur ulang untuk jarak sentuh dan keterbacaan.

## Light/Dark Mode dan tipografi

- Kasir menyimpan tema pada `localStorage` dan memberi class `.dark` pada `.app-shell`. Aturan dark mode eksplisit banyak berada di `style.css`; beberapa halaman berwarna dengan nilai hard-coded (sebagian `operations.css`, `pages.css`, `reports.css`, serta tabel/label) tidak memiliki pasangan dark yang terdefinisi di file terkait.
- Owner punya pilihan tema tersendiri yang tersimpan dengan key `kino-owner-theme`; variabel permukaan dasar sudah ada di `owner.css`, tetapi `owner-dashboard.css` hanya memberi override khusus untuk beberapa status. Palet halaman Owner dan Kasir tidak memakai satu sumber tema bersama.
- Login dan Absensi memakai `.owner-login-page` tanpa class tema dari aplikasi; keduanya tidak terhubung ke pemilih tema.
- `style.css` menetapkan DM Sans, sedangkan `typography.css` mencoba menerapkan Inter untuk teks dan Plus Jakarta Sans untuk judul. Owner/login juga memiliki deklarasi DM Sans. Override spesifik/urutan CSS membuat hierarki font sulit diprediksi. Beberapa ukuran komponen pada CSS lama hanya 6–10px; override typography memperbaiki beberapa elemen, tetapi belum seluruh metadata/kontrol.
- Status sering menggunakan kombinasi warna dan teks, yang baik; konsistensi kontras, fokus keyboard, dan pembaca layar belum bisa dipastikan tanpa pengujian runtime.

## Kesimpulan audit

Prioritas utama bukan menambah dekorasi, melainkan membedakan **tindakan utama**, **data nyata**, dan **informasi sekunder**. Mulai dari alur checkout Kasir, transparansi data prototipe, penyederhanaan dashboard Owner, kemudian konsistensi halaman operasional dan tema. Sebelum implementasi, rencana pada [`REDESIGN_PLAN.md`](REDESIGN_PLAN.md) perlu ditinjau dan disetujui.
